Where agents work



One folder per action
features/notes/create/
├── contract.ts       Shared request and response schemas
├── client.ts         Typed HTTP call and response validation
├── state.ts          Mutation, loading/errors, list refresh
├── server.ts         Validate, authorize, write with Drizzle
├── contract.test.ts
├── state.test.ts
└── server.test.ts
UI emits actionstate.tsclient.ts → HTTPserver.ts → SQLiteresponse → cache → UI
Pages and components consume state. They do not own endpoint URLs, network calls, cache mutation, or stream parsing. Each feature is one Bun workspace with explicit exports. An agent can own one action and its named UI files.
Parallel development, one merge gate
T3 brief / issueHost + worktreeOwned feature pathsRequired checksAgent merges PR
Root, feature, and scoped AGENTS.md files explain action ownership, commands, boundaries, data isolation, and evidence. Coordinate shared contracts/migrations/manifests in the task brief. The merging agent fixes its integration failures.
Verified after the refactor: 48 tests; full check in about 8 seconds. Action tests cover real SQLite/Hono requests, query refresh after writes, denied-write cache behavior, split stream events, and import boundaries. Optional browser smoke covers real app behavior; model calls remain outside merge checks. Earlier environment/video verification is retained.
